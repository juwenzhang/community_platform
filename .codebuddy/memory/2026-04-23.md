## 重写 next-gen-document-editor change 文档

### 背景

原 `next-gen-document-editor` 的 OpenSpec 文档质量不高：
- 没反映已沉淀的 md-parser specs（边界混淆，重复造渲染引擎四级）
- 与 `article-storage-optimization` 的存储格式抢占冲突（自己定义 content_json 字段）
- 范围内混杂了 non-goal 内容（version 表 SQL、冲突 API）
- 缺 `specs/` delta，无法 archive
- 包名 `@luhanxin/editor` 太宽泛，未来与 code-editor / sql-editor 冲突
- 任务列表里有「现有文章迁移」与 storage-optimization 重叠

### 重写策略

**包名改为** `@luhanxin/doc-editor`（明确文档编辑器职责）

**范围聚焦**：仅做编辑态 + 主站接入。明确剥离协同、版本快照、AI、模板、移动端、自定义 Canvas/WebGL。

**与已沉淀能力的清晰边界**：
- `md-parser-react` 负责只读渲染（详情页），`doc-editor` 负责编辑态
- 二者通过 Markdown 字符串交互 —— **后端 API 完全不变**
- 编辑器内部用 ProseMirror JSON，仅在草稿 IndexedDB 中持久化，远程保存时序列化为 Markdown
- Markdown 转换器复用 md-parser-core 的 `parseMarkdownToAst` 拿 mdast，避免双侧 AST 不一致

**11 个关键技术决策**：
1. TipTap v2（vs Slate / Lexical / 原生 ProseMirror）
2. 包名 `@luhanxin/doc-editor`
3. 数据交换格式：Markdown 字符串（不引入 JSON 字段，不动后端）
4. Markdown 转换器：自研 + 复用 md-parser-core 的 mdast
5. 代码高亮双栈：编辑态 lowlight（轻量同步），只读态 Shiki（重量异步）
6. Slash 命令架构：基于 @tiptap/suggestion + tippy.js
7. 自动保存：IndexedDB 防抖 800ms + 远程定时 30s + 强制保存按钮
8. 草稿生命周期：本地存 PM JSON、远程存 Markdown；本地 updatedAt > 服务端时弹窗恢复
9. 保存冲突：简单 last-write-wins + 提示，不做复杂合并
10. 不引入虚拟列表 / Canvas / WebGL（编辑态用 ProseMirror viewportMargin 足够）
11. 包结构：core/blocks/slash/menu/convert/autosave/react 7 模块

### 重写产出

- `proposal.md` — 重写：明确边界、Non-goals 完整、Capabilities 精确、Impact 详细
- `design.md` — 重写：11 个 Decision、Risks、Migration、Open Questions

## 第六轮：Phase 4 持久化层完整实施

### T4.1 IndexedDB 草稿存储（`autosave/DraftStore.ts`）

- 基于 `idb` 封装，DB_NAME = `luhanxin-doc-editor`，版本 1，单 store `drafts`
- Schema: `{ id, articleId|null, contentJson, contentMarkdown, updatedAt, version }`
- 索引：`by-articleId`、`by-updatedAt`
- API：`saveDraft / loadDraft / loadByArticleId / listDrafts / deleteDraft / cleanupOld / clearAll / closeDB`
- 清理策略：30 天保留 + 50 条上限（先删过期，再删超量的最老）

### T4.2 useAutosave Hook（`autosave/useAutosave.ts`）

- 输入：`{ editor, draftId, articleId, onRemoteSave?, debounceMs=800, intervalMs=30000, disabled? }`
- 输出：`{ status, lastLocalSavedAt, lastRemoteSavedAt, lastError, forceSave, isDirty, isOffline }`
- 状态机：`idle → saving-local → saved-local → saving-remote → saved-remote | error | offline`
- 本地：每次 editor update 防抖 800ms 写 IndexedDB
- 远程：定时 interval 调 onRemoteSave（仅 dirty && online 时）
- 离线：navigator.onLine === false 跳过 remote，`online` 事件恢复立即 forceSave
- beforeunload：有 dirty 时阻止默认（浏览器弹提示）

### T4.3 草稿恢复（`autosave/useDraftRestore.ts` + `DraftRestorePrompt.tsx`）

- Hook 在编辑器挂载时异步 loadDraft，与 `serverUpdatedAt` 比对
- 仅当 `draft.updatedAt > serverUpdatedAt + thresholdMs(1000)` 时才提示
- 新建场景（serverUpdatedAt == null）跳过（避免覆盖空页面）
- 弹窗：`DraftRestorePrompt` 纯 UI 组件
  - 展示 "X 分钟前 / X 小时前 / X 天前" 相对时间
  - 「恢复本地草稿」→ setContent + 清除 pendingDraft
  - 「放弃本地草稿」→ deleteDraft + 清除 pendingDraft
  - 支持 `renderDescription` 自定义描述

### T4.4 SaveStatusIndicator（`autosave/SaveStatusIndicator.tsx`）

- 消费 useAutosave 的返回值，展示当前保存状态
- 文案矩阵：
  - idle → "已同步 · HH:MM" / "未保存"
  - saving-local → "正在保存到本地..."
  - saved-local → "已保存到本地 · HH:MM"
  - saving-remote → "正在同步..."
  - saved-remote → "已同步 · HH:MM"
  - offline → "离线：内容仅保存到本地"
  - error → "保存失败：xxx" + 重试按钮
- CSS modifier: `--saving` / `--success` / `--error` / `--offline`
